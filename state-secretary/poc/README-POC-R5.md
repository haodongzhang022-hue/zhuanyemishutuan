# M4/M6 复合路由POC (R5) · 补齐复合缺口
> 架构·经理 | 承接 R4(m1_router.sh 单直连), 叠加多槽位二次扫描 + 会话编排判定

## 背景(从 R4 暴露的复合缺口)
R4 结论第4点: 「当前 M1 仅单岗位路由。复合意图需**多槽位二次扫描 + M4 编排判定** —— 属 R5 开发项」。
R4 中 `"既要架构设计又要落地开发"` 只路由到 developer 单岗位, 丢失复合诉求。

## 本 POC 解决的问题(对应 M4/M6)
| 能力 | R4(m1_router.sh) | R5(m2_router_composite.sh) |
|------|------|------|
| 岗位命中 | 仅记**首个/单岗位** | **多槽位二次扫描**, 记录所有命中岗位 |
| 复合判定(M4) | 无 | 命中岗位数>=2 → 复合候选; 1 → 单直连 |
| 复合装配(M6) | 无 | 同session并装多岗位, 校验 composite 能力 |
| 前缀稳定 | 一会话一行业 | 一会话一行业, 岗位前缀=固定并集零突变 |

## 运行
```bash
cd poc
./m2_router_composite.sh industry-register.yaml "<一句话意图>"
```

## 结论
1. **复合缺口已补**: 多槽位二次扫描 + M4 判定, 可识别 ≥2 岗位复合诉求并 M6 并装同会话 agent。
2. **量化信号②达成**: 复合≥2岗位同会话运行已验证。
3. **前缀稳定策略保持**: 复合不跨行业, 岗位前缀取该行业固定并集, 零突变, 不破坏缓存命中键。
4. **边界**: 同会话复合仅限同行业多岗位; 跨行业/含不可复合岗位 → 判定拆新session 走 M5 交接卡(R6 项)。
5. **待扩展(R6)**: 多行业单元路由 + M5 跨单元交接回归; 复合岗位依赖序调度(DAG 波次) → 需扩展第二行业单元后在源仓回归。

## 技术栈结论(延续 R4 拍板)
- 仍为「bash/awk 轻量脚本 + YAML 声明式」, **无需重前端**, M4/M6 编排判定可在脚本层以多槽位+组合判定实现。
- 为将来 M5 交接/多单元引入第二行业单元预埋了 `unit/industry` 独立声明结构, 便于横向扩展。
