# POC 验证方案：token 消耗与缓存命中对比

> 目标：可验证地对比「秘书管理状态」vs「全量历史」两种编排在同一多轮任务下的 token 消耗与缓存命中，量化收益。

## 1. 场景定义

- 单会话内连续执行多次任务（如 20-50 个子任务 / 轮次）。
- 对照两组：
  - **A 组 · 秘书态**：本方案——稳定前缀 + 折叠索引 + 汇总态驱动每步。
  - **B 组 · 全量历史**：论文 Memory 基线——每步追加完整历史到 prompt。

## 2. 观测指标

| 指标 | 采集方式 |
|------|----------|
| 累计输入 token | 各轮 prompt 输入长度求和（打印/埋点） |
| 累计输出 token | 各轮模型输出长度求和 |
| 缓存命中率 | 相同前缀轮的命中标记 / 命中字节占比 |
| 任务完成正确率 | 最终结果与预期对照（对齐论文 score） |
| 平均每轮前缀长度 | 反映前缀是否漂移 |

## 3. 执行步骤

1. 固定系统前缀 + Schema 定义（两组的系统部分一致）。
2. B 组每步把全量历史拼进 prompt；A 组每步把历史折叠为索引 + 汇总态。
3. 记录每轮 prompt 前后两半长度、输出长度、是否命中缓存前缀。
4. 连续执行至任务数 N，汇总累计指标。

## 4. 预期结果与判据

| 指标 | B 全量历史 | A 秘书态 | 通过判据 |
|------|-----------|----------|----------|
| 累计输入 token | 近似平方级增长 | 近线性（前缀稳定） | 硬阈值：A累计输入token ≤ B×1/10 |
| 前缀长度 | 随会话增长漂移 | 稳定 | 硬阈值：A前缀长度近常数，逐轮方差有界（σ ≤ 均值的 5%）；近线性增长率 < B 的 5% |
| 缓存命中率 | 低（前缀漂移） | 高 | 硬阈值：A命中率 ≥ B×2 且 ≥ 60%（绝对） |

**PASS/FAIL 判定（可复现）**：以上三项硬阈值（A累计token ≤ B×1/10 ∧ 前缀近常数方差有界 ∧ A命中率 ≥ B×2 且 ≥60%）须全部满足，三者全过才判 🟢 PASS；任一项不满足即 🟥 FAIL。对齐论文数字参考（Warehouse 200 步：Memory 6.1M vs SKILL.state 122k，约 1/50）——本判据的 1/10 为主判据，方向与量级一致且为可实现硬阈值。*

## 5. 验收对应
- 对应 US-4 缓存命中（前缀稳定）；对应 Q3/Q5 的机制在真实多轮会话中被验证。
- POC 落地为新增模块的 demo/benchmark（见 module.md），运行输出对比报告供 CP2 人确认放行。
