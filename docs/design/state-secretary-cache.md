# 缓存命中保障 + 丢弃时机机制

> 目标：保证同一对话提示词前缀稳定，缓存命中率高、成本低；并解决常驻 agent 上下文无限增长的丢弃时机，对齐 US-4 + Q3。

## 1. 设计动机

缓存命中取决于 prompt **前缀稳定性**。若历史持续追加、前缀漂移，则命中率下降。本机制把「折叠 + 编号」固化进稳定前缀，保证多次执行命中缓存。

## 2. 提示词结构（稳定前缀）

```
┌─ 固定系统前缀（角色/技能说明/Schema 定义）          ← 恒定，命中
├─ 当前会话汇总态（progress/decisions/open_items）     ← 短、稳定，命中
├─ 折叠索引块（context_id 列表 + 微摘要）             ← 只索引不常驻原文
├─ 最新观察 / 本步任务指令                             ← 变化，不拖累命中
└─ 指令（要求输出状态补丁 + 结论，不追加本步推理到前缀）
```

- 折叠块以**索引列表**形式稳定呈现，编号规则确定 → 前缀不随对话增长漂移。
- 本步推理不作为历史追加进前缀（借鉴论文：校验状态补丁后丢弃本步推理），避免污染稳定前缀。

## 3. 命中保障策略（US-4）

1. **前缀固化**：系统前缀 + Schema 定义恒定，不随会话长度变化。
2. **折叠只索引**：历史内容折叠为 `context_id` 摘要列表，原文不进入前缀。
3. **汇总态短且定长**：progress/decisions/open_items 保持精简，字段固定 → 前缀稳定。
4. **编号确定性**：`context_id := task_id-seq` 规则确定，折叠/展开不改变已稳定前缀结构。

验收：同一对话多次执行 → 前缀稳定不漂移；折叠与编号不破坏前缀稳定 → 满足 US-4。

## 4. 丢弃时机机制（防常驻 agent 无限增长）

针对 L1 秘书长 / L2 状态管理秘书等**常驻 agent**（即使依赖助理状态管理，助理状态也会持续增长）：

### 4.1 可丢弃对象
- 已归档任务（`status: stopped`）的折叠块原文引用。
- 低价值、已结束、不再追踪的中间推理/临时观察。
- 已固化为「决策记录 / Schema / 角色词」的内容（不再需要原文重复携带）。

### 4.2 丢弃规则（保守、可回查）
- 丢弃前确认该 `context_id` 的原文已归档且 `loc` 可定位，能按索引找回。
- 保留：高价值决策摘要、开放项、活跃任务索引、Schema 定义。
- 丢弃时机：状态补丁校验通过后 / 任务归档时 / 前缀即将超预算阈值时。

### 4.3 效果
- 常驻 agent 只保留「高价值汇总 + 活跃索引」，随会话增长缓慢，命中率得以长期维持。

## 5. 与折叠/检索衔接
- 丢弃的是「低价值原文常驻」，保留的是「高价值汇总 + 可回查索引」——由 fold.md 的检索协议兜底，丢弃不丢失上下文。
