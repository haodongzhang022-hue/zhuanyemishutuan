# 循环熔断守卫 · 设计（轮次预算 + 非必要修复最多 1 次 + 静默交接）

> module: zhuanyemishutuan · docs/design
> Ref: #14
> 载体：`state-secretary/src/secretary/loop/loop_guard.py`（`LoopGuard`）
> + `state-secretary/src/secretary/session/session.py`（门面集成）
> + `state-secretary/src/secretary/handoff/`（`wake` 静默交接字段）

## 1. 问题：为什么会陷入循环

此前 Issue 的「评审打回 → 开发修正 → 复评」缺乏上界，一次修复往往又产生新的
可挑项，形成**永动循环**。实测形态有两类：

| 形态 | 例 | 为什么停不下来 |
|---|---|---|
| 门禁往返无上界 | 🔴 反复修、反复被打回 | 每次都有"新的必修项"（口径/边界逐轮加严） |
| **非必要项无限追修** | 🟡 清单每轮换一批 | 无必要修复（非门禁）也各占一轮，且**每轮都能新挑出几条** |

现行机制只有一句软约束（角色提示词「不合格打回，最多 3 次」），
**不可执行、不持久、不跨 agent**：换一个 agent 接手，轮次计数归零，循环复活。

## 2. 设计目标

- **可判定**：是否继续修复，由**预算数字**决定，不由 agent 自述决定。
- **有上界**：门禁轮次、非必要轮次、修复总轮次三道独立上界。
- **能感知循环**：同一问题反复报（停滞）→ 不等预算耗尽就熔断。
- **静默交接**：熔断后交接给下一个 agent 时**不唤醒**——只登记事实，不得据此再开一轮。
- **不复活**：预算状态持久化，跨实例/跨 agent 可读；恢复只能靠**人工解锁**。

## 3. 三道（+1）上界

| 上界 | 默认 | 语义 |
|---|---|---|
| `max_rounds` | 3 | 门禁（🔴）修复轮次；与「最多打回 3 次」口径一致 |
| `max_advisory_fix_rounds` | **1** | 非必要（🟡）修复轮次：**"无必要修复的内容，最多修 1 次"** |
| `max_total_rounds` | `max_rounds + max_advisory_fix_rounds + 1`（=5） | 修复轮次硬上界，防 🔴/🟡 **交替出现**绕过前两道 |
| `max_stall_repeats` | 2 | 同一整改项**指纹**连续出现次数 → **停滞循环**立即熔断 |

### 判定顺序（确定性，与调用顺序无关）

```
已熔断 → 停滞（指纹重复）→ 总轮次上界 → 门禁上界 → 非必要上界 → CLEAR（无需修复）
```

### 四类处置动作

| action | 触发 | `wake` | 含义 |
|---|---|---|---|
| `clear` | 无 🔴 无 🟡 | `False` | 无需修复，门禁放行（**不消耗任何预算**、不唤醒） |
| `fix` | 有 🔴，门禁预算内 | `True` | 允许修复并唤醒一轮复评 |
| `fix_last` | 仅 🟡，非必要预算内 | `True` | **最后一次**修复（用完即熔断） |
| `fuse` | 任一上界耗尽 / 停滞 / 已熔断 | `False` | **熔断**：不再修复、不再唤醒 |

`clear` 不消耗预算，保证"门禁放行"不被空转轮次挤掉预算。
`fuse` 为**终态**：之后的任何轮次（含"本轮无新项"）都保持熔断，不得降级为 `clear`。

## 4. 静默交接（不唤醒）

熔断后交接给下一个 agent，走的不是常规接力，而是**静默交接卡**：

```python
sec.review_round(blocking=0, advisory=1)   # 第 1 次 🟡 → fix_last
d = sec.review_round(blocking=0, advisory=1)  # 第 2 次 🟡 → fuse（fused_now=True）
card = sec.silent_handoff("秘书·评审", "秘书·开发",
                          "Issue #14 循环熔断交接", open_items=["🟡 结转项"])
```

- 卡面 `wake=False`（**落盘持久化**，跨实例读回不丢，否则下一个 agent 读回默认
  `True` → 静默交接被当成可唤醒接力 → 循环复活）；
- 卡面 `fuse_reason` + `context` 内嵌轮次/预算快照（
  `silent_handoff_payload()`），接收方一眼看到"为何不得再开一轮"，不必自行推理；
- 接收方用 `SecretarySession.inherit_silent_handoff(payload)` 起手即熔断，
  **轮次计数一并继承**——换 agent 不重置预算。

### 唤醒闸门（熔断后禁止自动复活）

`SecretarySession.create_handoff(wake=True)` 在本会话已熔断时抛
`RuntimeError`；熔断后只允许 `silent_handoff()`（`wake=False`）。
即：**熔断后不存在"自动/误写的唤醒式交接"路径**。

`HandoffBus.create_handoff` 对 `wake` 做**严格 bool 校验**：`wake="false"`
这类真值字符串抛 `TypeError`，防止熔断语义被静默绕过。

## 5. 恢复途径：仅人工解锁

| 手段 | 说明 |
|---|---|
| `resume_loop(by="张三", reason="确认收口")` | **唯一**恢复预算的途径；`by` 不可为空（**禁止匿名复活**），留痕进 `history` 与 `resume_count` |
| `fuse_loop("上游叫停")` | 反向：人工/上游**直接叫停**循环（不等预算耗尽） |

`resume` 会**重置修复预算**（否则预算本已耗尽，翻标志位后下一轮立即再熔断，
解锁无意义），但保留 `round_no`/`history` 作为审计轨迹，并清空停滞指纹。

## 6. 跨 agent 传导

- 预算状态落 `<数据根>/loop/<session_id>.json`（与会话数据同根，原子写入
  `tmp + os.replace`）；**同一 session_id 的新实例读回熔断态后仍熔断**；
- 静默交接卡把熔断事实**主动**传给下一个 agent（不需要它回读上一实例的磁盘）；
- 两个方向都堵住"换个 agent 就复活循环"。

## 7. 健壮性与边界

| 场景 | 行为 |
|---|---|
| 状态文件损坏 / 非对象 JSON（`[]`、`"str"`、坏 JSON） | 视为**全新状态**（宽进不炸，不因坏文件卡死会话） |
| 字段类型不符（轮次为字符串/布尔、`history` 非数组） | 字段级降级为默认值，不抛异常 |
| `session_id` 非 `[A-Za-z0-9_-]+` | `ValueError`（不参与路径拼接，防穿越） |
| 预算参数为负/布尔/浮点 | `ValueError`（拒绝静默取整） |
| 交接卡出现未知字段（未来版本写入） | 读取时忽略，不失败 |
| 旧交接卡缺 `wake` 字段 | 默认 `True`（常规接力，向后兼容） |
| `delete_session()` | 一并清理 `<数据根>/loop/<session_id>.json`，同 id 复建不带陈旧熔断 |

`preview` / `preview_round` 为**纯函数**：不消耗预算、不落盘，供预演/留痕使用。

## 8. 与门禁流转规范的关系

`docs/secretary-gate-workflow.md` 的「🔴 必修 → 回转；🟡 建议」加入熔断口径：

- 🔴 回转**计入门禁预算**（默认 3 次）→ 耗尽即熔断；
- 🟡 回转**最多 1 次**，第 2 次同类不作回转，改**结转**（登记不修）并静默交接；
- 熔断后评论/交接卡必须带 `wake=False`，接收方不得自动开新轮；
- 恢复须人工 `resume`（留痕）。

## 9. 验证

`state-secretary/tests/test_loop_guard_issue14.py`（**62 项**，全量 370 项）：

- ① 门禁上界（含 `preview` 纯函数性、`clear` 不耗预算、熔断终态不得降级为 `clear`）；
- ② 非必要"最多 1 次"（含门禁轮重置配额的反向对照）；
- ③ 总轮次硬上界（**门禁预算仍在**却熔断 → 证明拦住循环的是总上界本身，非门禁上界顺带）；
- ④ 静默交接（落盘跨实例保真、熔断拒绝唤醒式交接、`wake` 严格 bool、旧卡默认 `True`）；
- ⑤/⑤b 跨 agent 不复活 + 停滞感知（指纹相同即熔断且预算充足；不同指纹不熔断；`clear` 不推进停滞）；
- ⑥ 人工解锁（空 `by` 拒绝、解锁恢复预算、`fuse` 幂等）；
- ⑦ 持久化健壮性与会话生命周期回收；
- ⑧ 门面集成（预算随 `summarize_for_upstream` 上行）。
