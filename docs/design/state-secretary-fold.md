# 上下文折叠 / 编号 / 检索协议

> 目标：实现「原始上下文按任务折叠并编号，唯一可检索；原文不常驻 prompt，缺时精确找回」，对齐 US-2 + Q2 + Q3。

## 1. 设计动机

论文校验后丢弃本步推理，避免 prompt 无限变长；但丢弃即丢原文。本方案改为**保留原文 + 按任务折叠编号**：原文不删（自然存在于原始对话），但**不常驻 prompt**，以带编号的索引态驱动每步。

## 2. 折叠触发：自动化优先（Q2）

- **一开始就按任务折叠**（类 todolist），**不是做完再折叠** → 防 UI 跳变、稳定前缀。
- 开发内容归类到某任务下 → 自动折叠归入该 `task_id`。
- 任务结束且不再追踪 → 自动停止追踪（折叠块归档、移出活动索引）。
- 默认大部分走自动规则；**有疑问才问**（不每步 AI 评估）→ 保证秘书上下文纯净、能力充足。

## 3. 上下文编号与索引

### 3.1 编号规则（context_id）
每段可折叠的原始上下文赋予全局唯一编号：

```
context_id := {task_id}-{seq}
示例：t-001-0001, t-001-0002 ...
```

- `task_id`：所属任务/小目标（对齐 schema.task_id）。
- `seq`：任务内自增序号，保证同任务内唯一。

### 3.2 折叠态（索引块）
每个 task 维护一张索引表，折叠态只存索引 + 微摘要，不存原文全文：

```jsonc
{
  "task_id": "t-001",
  "title": "完成状态最小集设计",
  "folded": true,
  "index": [
    { "context_id": "t-001-0001", "summary": "澄清 Q4 schema 最小集", "loc": "conversation:ts / file:path" },
    { "context_id": "t-001-0002", "summary": "定义 ext 扩展区", "loc": "..." }
  ],
  "status": "in_progress"
}
```

- `loc`：原文所在位置（原对话段 / 落盘文件 / 仓库路径），供精确找回。
- 折叠块**只索引不常驻** → 满足 US-2 / US-4。

### 3.3 原文存储位置（Q3）
- **不额外冗余存储**：原始原文自然存在于原始对话内，仅登记 `loc` 引用。
- 只存储二次管理的 todolist/任务小目标（精简信息层）交给状态机秘书驱动下一轮对话。
- 末端 agent 可维持状态到任务结束；对话归档后原文随归档保留，索引指向归档位置。

## 4. 折叠状态机

```
[活动 task] --任务内容归类/超阈值--> [折叠态 folded]   # 默认折叠，自动化
[折叠态]    --需精确原文--> [展开检索 context_id]        # 临时取出，用完回归
[折叠态]    --任务结束且不再追踪--> [归档 stopped]       # 自动停止追踪
```

- 状态管理基本在 todolist/任务小目标这一层，不是展开的全文。
- 非需要默认折叠，防 UI 跳变。

## 5. 检索协议（缺原文时精确找回）

1. 需要某段原文 → 凭 `context_id` 定位折叠块。
2. 读该块 `loc` → 在原始对话 / 归档 / 文件精确截取该段。
3. 取回后仅在本步使用，不重新常驻 prompt。

校验：多轮累积后秘书仅持折叠索引；对任意 `context_id` 能精确还原对应原文 → 满足 US-2。
