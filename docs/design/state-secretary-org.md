# 层级秘书组织模型

> 目标：定义 L0-L3 层级秘书角色、升降边界规则、以及与 M5 交接总线的关系，支撑 US-1/US-3。

## 1. 设计动机

SKILL.state 由单一 agent 管理状态，随会话增长无隔离。本方案引入**层级秘书**：每层只掌握该层有效上下文，向上层层提交**汇总态**而非全文，实现噪声隔离与宏观-微观解耦。

## 2. 层级总览（L0-L3）

| 层级 | 角色 | 管理范围 | 常驻性 | 掌握内容 |
|------|------|----------|--------|----------|
| L0 | 人机交互秘书 | 与人类交接 | 平台入口常驻 | 用户需求、进度对外呈现 |
| L1 | 秘书长 | 全体秘书团队调度 | 常驻（带丢弃机制） | 各分区宏观进度、资源调度 |
| L2 | 状态管理秘书 | 分区功能域下秘书 | 常驻（域级） | 该域汇总态 + 域内会话清单 |
| L3 | 会话/对话秘书 | 单 Issue/PR/对话 | 随会话创建/归档 | 该会话状态机（todolist/进度/决策） |

职责要点（对齐 Q1 澄清）：
- 对话内同一任务不分级，防止过度参与冗余。
- 开发线 = 开发小组（开发+评审循环）+ 会话秘书状态机 + 偶尔经理/架构师分配任务。
- 秘书长不进入具体对话（将在外军令有所不受），仅在架构/任务偏移需干预时介入。

## 3. L0-L3 职责与边界

### L0 人机交互秘书
- 与人类交接进度、承接需求，转交秘书长安排。
- 只呈现汇总信息，不携带底层全文。

### L1 秘书长
- 各秘书向其汇报；分析、拆解、安排任务。
- 类经理角色，但管理对象是秘书团队。
- **边界**：不进入具体对话前线；只在偏移时干预。

### L2 状态管理秘书（小组长）
- 管理分区功能域下的 L3 秘书们。
- 汇聚域内各会话的汇总态，向上提交域级宏观状态。

### L3 会话/对话秘书
- 每个 Issue/PR/对话独享一个负责秘书，责任到人（agent）。
- 工作安排、进度检查专职；驱动状态机对话管理秘书。
- 对话可新开承接新状态任务，或做几步再归档；末端 agent 可维持状态到任务结束，不因对话归档新开 agent。

## 4. 自动分配机制（US-1）

- 事件触发（Issue/PR/对话创建）→ 自动实例化一个 L3 会话秘书，绑定独立命名空间上下文。
- 各 L3 环境彼此隔离，不共享上下文 → 满足 US-1 验收。
- 会话关闭/任务完成 → 该 L3 秘书归档停用，可回收环境。

## 5. 层级向上提交协议（US-3）

下级 → 上级仅提交**汇总结构化状态**（见 schema.md §3 最小集），不含原始全文：

```
progress     # 进度（纯数值 [0,1]，见 schema.md §3.1；完成态由 status 裁决）
decisions    # 本域关键决策（折叠后的要点，非全文）
open_items   # 开放项 / 阻塞点
context_ids  # 涉及的本层上下文索引（可回查）
```

- 上级状态不包含下级无关的其他项目上下文 → 满足 US-3 验收。
- 上级如需细节，按 `context_id` 索引精确下钻，而非全量携带。

## 6. 与 M5 交接总线的关系

- 层级边界与升降规则**对齐 M5 交接总线**的事件语义：L3 会话秘书的向上提交即一次「汇总态交接」，携带 `context_id` 列表，确保总线上下级可衔接追踪。
- 层级升降规则：默认稳定在既有层级；仅当任务规模越界（域内会话数超阈值 / 需跨域资源）才升级到 L2/L1 协调，避免频繁升降造成上下文抖动（对齐 Q1「防过度参与」）。

## 7. 防上下文无限增长

- L3 会话秘书受状态机约束（todolist 精简层），对话可归档换新。
- L1/L2 常驻秘书上下文持续增长 → 引入 cache.md §4 丢弃时机机制，在合适时机丢弃低价值块，仅保留高价值汇总与索引。
